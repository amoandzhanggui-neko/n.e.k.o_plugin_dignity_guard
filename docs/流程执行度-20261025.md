## 六、核对过程中顺带发现的三件事

### 6.1 受控集不认 `.gitignore`（设计取舍，非 bug）

`neko_review_gate.js` 的受控集是 **default-deny + `readdirSync` 递归全收**，除文档白名单外所有文件都受控，**故意不认 `.gitignore`**（防有人用忽略文件藏代码）。

代价：**任何缓存放在仓库里，都会让闸每跑一次就红。**
已把 `state.sh` 的测试缓存挪到仓库外 `~/.cache/neko-dignity-guard/`，受控文件 **36 → 35**。

### 6.2 日志文件名按"进程启动日"定，跨天不滚（宿主侧）

`N.E.K.O/utils/logger_config.py:134`：

```python
log_filename = f"{app_name}_{service_name}_{datetime.now().strftime('%Y%m%d')}.log"
```

文件名在 `setup_logging` 时算一次，之后不再变；轮转用 `RotatingFileHandler`（**按大小**，不按日期）。

证据：
- `N.E.K.O_Plugin_dignity_guard_20261018.log` 里装着 **10-18、10-19、10-20、10-21、10-22 五天**
- `N.E.K.O_Plugin_dignity_guard_20260919.log` 在 **10-11** 还在写

**排障时按文件名找日期，一定找错。** 这是宿主代码，按 skill 铁律 6「不改宿主代码」，只记录不修改。

### 6.3 插件自身完全不配日志

- `plugin.toml` 无任何 log 配置项
- `__init__.py` 连 `import logging` / `getLogger` 都没有

日志由宿主统一管：`plugin/logging_config.py` → `utils/logger_config.RobustLoggerConfig`，
级别由环境变量 **`NEKO_LOG_LEVEL`**（TRACE/DEBUG/INFO/WARNING/ERROR/CRITICAL）控制，
落盘 `AppData/Local/N.E.K.O/logs/`，插件单独一份在 `logs/plugin/<插件名>_<日期>.log`。
仓库**禁止 loguru**，CI 有 `scripts/check_no_loguru.py` 守门。

> 排查提示：`AppData/Roaming/N.E.K.O/neko-electron-debug.log` 是 **Electron 前端**日志，
> 里面永远查不到插件行为（实测今天 6553 条里 0 条 dignity）。别用它判断插件死活。
