### 铁证：无 `.git` 的完整副本上，旧版说「可交付」

用 `git archive HEAD` 导出一份**文件齐全、只缺 `.git`** 的副本（80 个文件，与 `git ls-files` 一致），
并配好宿主副本，然后用同一份代码跑：

| 版本 | 输出 | rc |
|---|---|---|
| 去掉 `.git` 那条检查（= 旧行为） | `[√] 全部受控文件与会审登记一致（53 个）。可交付。` | **0** |
| 现在的版本 | `[x] 前置体检不通过：… 下缺 .git/ ⟹ **拒绝给结论**` | **1** |

原因：判红 3（工作区必须干净）与判红 9（契约变更次数）都靠 `git status` / `git log`。
非 git 目录里它们返回**空字符串**，被读成「一次都没改过」⟹ 放行。

这比红更危险：**红让人停手，假绿让人放心。**

### 顺手纠正我自己写错的注释

第一版注释写的是「受控文件集、台账链都靠 git」——**这是猜的，不是读的**。
`controlledFiles()` 是目录递归 `walk()`，根本不碰 git。注释已改准。

写错的注释比没注释更坏：它会让人以后按错误的因果去改代码。

## 五、顺带查实的行尾问题（只修了一个文件）

`neko_review_gate.js` 提交时 git 警告「CRLF will be replaced by LF」，而 `.gitattributes`
里明明写着 `*.js text eol=lf`。查下来：

| 文件 | 工作区 CRLF | HEAD 里 CRLF |
|---|---|---|
| `neko_review_gate.js` | 506 处 | **0** |
| `__init__.py` | **3537 处** | **0** |
| `i18n/zh-CN.json` | 291 处 | **0** |

所以：**仓库存的一直是 LF，工作区是 CRLF**。`.gitattributes` 的 `eol=lf` 只作用在 checkout 方向，
而这些文件从没被重新 checkout 过。

本轮只把 `neko_review_gate.js` 转成 LF，并**验证了它不改变任何东西**：

- 闸算的哈希：转换前后都是 `9f4607f595ffb177`（`sha16()` 有 `\r\n → \n` 归一化）
- git blob：HEAD 与索引都是 `bbe23ece…`，转换后 `git diff` 为空

`__init__.py`（3537 处）和 `zh-CN.json`（291 处）**没动**，入待办 T25。

理由：它们是插件主体文件，虽然按上面同样的机制推断"转行尾不改变哈希"，但**我只验了一个文件**，
不能把推断当成结论去批量改 4000 行。该单独一轮做、单独跑全量。

另记一个坑：转完之后 `git status` 报 `M`，但 `git diff` 是空的、字节数完全一致。
原因是 **stat 缓存**（mtime 变了）。`git add` 让它重算，发现 blob 没变 ⟹ 立刻干净。
**看到 `M` 不能立刻认为"有改动"**，得看 `git diff`。
